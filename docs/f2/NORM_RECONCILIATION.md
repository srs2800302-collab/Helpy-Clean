## Negative Evidence Semantics

The final corrective pass also replaces previously shared failures that tested
a neighboring rule. Examples: NTF.6 now actually republishes after exclusion and
attempts reentry; RET.8 actually attempts to apply a future retention version to
an old source; MON.3/MON.23 exercise wrong half-up results in actual persisted
payouts; RES.8 attempts to send an incorrectly double-rounded compensation;
INF.9 attempts canonical scope-text injection; INF.12 queries an old order using
the current rather than snapshotted catalog. Actual close/select and completion
race failures are attached to their own norms, not unrelated closed-case calls.

A typed Failure is required when the operation should reject. Its witness stores
the concrete sanitized command input and attaches rollback evidence only after
the harness checked the real before/after repository state. Provider bearer
proofs are not copied into this metadata.

Some valid negative inputs correctly return a normal typed result: an empty
specialization returns an empty feed, duplicate valid rule bindings produce one
block, an unknown outcome does not consume a timer reset, a zero payout produces
no instruction, and a hidden review is absent from public aggregates. These
witnesses execute the actual read/calculation/command and assert the forbidden
effect is absent. They do not fabricate a Failure or catch a deliberately false
assert. Structural source/exemplar/compiler controls remain explicitly separate.

The stronger witnesses exposed further implementation gaps, now guarded:
unsupported fields cannot enter a canonical ScopeItem or ResolutionDecision;
exceptional completion cannot use stale main/support history or an inconsistent
accepted-order cancellation context; premature normal payout does not consult a
destination service; a financial retention record cannot borrow a version that
became effective after its anchor. Photo identity validation does not add an
unapproved global reuse restriction between distinct configured requests.
