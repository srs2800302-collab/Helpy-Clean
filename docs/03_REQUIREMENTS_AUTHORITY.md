# Helpy — иерархия источников требований

При конфликте действует следующий приоритет:

1. Новое явное решение владельца.
2. Утверждённые бизнес-требования, Registry и продуктовые контракты.
3. Принятая владельцем документация нового репозитория.
4. Legacy implementation — только источник для анализа.

Документ нового репозитория до явной приёмки владельцем является кандидатом, а не утверждённым решением.

Неясность не разрешается предположением разработчика.

Техническое решение не требует отдельного согласования только если оно одновременно:

- не меняет бизнес-поведение;
- не меняет принятую архитектурную границу;
- не меняет порядок разработки;
- не создаёт новую обязательную dependency;
- не нарушает ранее принятое решение.

Изменение бизнес-логики или архитектурной границы должно быть выявлено и согласовано до реализации.

Техническая оптимизация не является разрешением на изменение требований.
